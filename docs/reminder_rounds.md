# 2回の手動リマインド

第1回・第2回はそれぞれ予定日、予定時刻（日本時間）、文面、宛先確認、プレビュー、配送結果を持つ。日時に到達しても送信しない。管理者の送信開始後は既存のサーバー配送workerが継続する。

## 保存と互換性

|項目|第1回|第2回|
|---|---|---|
|テンプレート|events.reminderMailTemplate|events.reminder2MailTemplate|
|予定日時|reminderSendAt|reminder2SendAt|
|予定日・時刻|reminderPlannedDate / reminderPlannedTime|reminder2PlannedDate / reminder2PlannedTime|
|ジョブ|reminder-{eventId}|reminder2-{eventId}|
|配送|{participantId}_reminder|{participantId}_reminder2|

APIのround省略は1。1・2以外は拒否する。旧設定・旧ジョブ・旧配送は第1回として参照し、移行や一括書換えは不要。旧絶対日時は日本時間の入力欄に変換して表示する。日時なしの旧完了ジョブも履歴として参照でき、新規に作り直さない。第2回は必ず独立した設定を保存する。文面コピーは入力欄へのコピーだけで、明示保存まで書き込まない。コピー後も両回は独立し、連動上書きしない。

日付だけの下書き保存を認める。時刻がない場合に00:00などを補完しない。予定日・時刻が揃わなければ新規ジョブを作成しない。送信予定は自動送信時刻ではなく、確認画面に表示する運用上の予定であり、管理者は手動で前倒し・遅延送信できる。完了済み・作成済みジョブの再開は固定済みsnapshotを利用する。

## 対象と安全確認

各回の作成時点で、確定済みの有効な申込と全有効資格を正本から再抽出する。従来の安全条件（当選通知sent、追加当選通知未確定・unknownの停止、疑わしい重複の停止）は維持する。通常/繰り上げ、複数programを区別せず1申込1通。第1回後に追加された申込は第2回で抽出する。同一アドレスの別申込を自動統合しない。

宛先・資格・人数・時間・通知配送状態・テンプレートversion・予定日/時刻・回を確認用fingerprintへ反映。旧ジョブのfingerprint互換性を維持する。ジョブ作成後の文面・問い合わせ先変更は既存配送を止めない。資格/宛先等の変更は送信直前に安全停止する。

各回のsent/unknownは再送しない。failedだけが従来の再試行・再確認の対象。復旧の確認値・配送記録は指定回のジョブに閉じる。途中で準備が失敗した新ジョブは作成時に固定した対象IDとsnapshotで再開し、後から文面や対象が変わっても置き換えない。並行準備で完了状態をreadyへ戻さない。

participantId/publicId/QR/参加証URL/参加資格/当選通知履歴はこの機能で更新しない。イベント/申込に「社内テスト除外」の機能は追加していない。正式イベントの既存テスト7件のリマインド混入問題は別途対応が必要。
